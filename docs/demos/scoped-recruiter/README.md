# Scoped recruiter source qualification

The same command arguments are rejected as an unknown flag on base
`a5194aea29f5e417c8dbc810a1f0253b2484f920`, then parse as scoped qualification
on the candidate. Its CLI source SHA-256 is recorded. Explicit fixture forge
and custody adapters then show a matching exact head admitted and a changed
custody head refused. An actual CLI control uses a fixture identity and
NullPanes: a live request refuses before the sudo-capable launcher, leaving
zero job records or launches.

Run `python3 docs/demos/scoped-recruiter/run.py` from the repository root.
[Output](output.log) and [timing](timing.log) form a terminal recording retained
with this source change. Download both and replay using
`scriptreplay --log-out output.log --log-timing timing.log`; output is also the
readable transcript. No inline player is assumed.

This is source qualification with fake authority adapters, not a deployed
identity, authenticated host attestation, real webhook, or live job. The
controller handoff is deliberately gated because the existing job launcher
uses sudo and the scoped principal has no such authority. Host provisioning,
identity-policy installation and recruitment activation require their separate
reviewed security migration. Merge recruitment remains off.
